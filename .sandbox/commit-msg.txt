chore: add the marketplace submission script

The community registry -- the de-facto plugin marketplace -- takes one PR
adding one file. That part is trivial; the reason this is a script is that the
gate around it is not. CI checks the dsh.bundle manifest, the repo age, that
the repo exists and is not archived, the entry's YAML shape, that the READMEs
regenerate, and that the release asset answers 206 to a ranged GET.

Everything except the age was verified locally first, by running the
registry's own check-submission.mjs against the entry: the age bar is the only
failure, and the checker itself says it re-runs by itself and needs no
resubmission. So the script exists to re-assert all of that on the day, then
fork, add the one file, and open the PR -- not to work around anything.

Two things it does deliberately:

- ASCII only. This file is read by Windows PowerShell as well as pwsh, and an
  em dash written as UTF-8 is read as GBK there, producing a parser error on a
  line that looks fine in an editor. The first version of this script had
  exactly that fault and failed to parse.

- The repo age is parsed with AssumeUniversal rather than a bare [datetime]
  cast. The cast applies the machine's timezone and silently relabels the
  instant: created at 16:25Z prints as "00:25 UTC" on a UTC+8 box -- the right
  duration, the wrong timestamp, and a reader would wait eight hours longer
  than they need to.

The entry itself lives in .sandbox/marketplace-entry.yml. The description
names only what the code does -- eight events, seven channels, severity mapped
to the fields Bark/ntfy/Telegram/webhook actually support -- because the
registry reads the description as a claim and checks it against the source.
